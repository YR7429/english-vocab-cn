## 一、特色

**分级明确。** 星级取自课标词汇表：两星为选择性必修、一星为必修、无星号为义务教育阶段已掌握。词表同时保留原始资料的星号，两者不一致时以课标为准。

**着力于熟词生义。** 这是本表最费心的地方：

- `！` 表示**无法联想**的生义（如 `policy` 的"保单"、`coverage` 的"新闻报道"）
- **加粗**表示**可以联想**的引申义（如 `edge` 的"刀刃"、`nail` 的"钉子"）

**变化只列不规则的。** 规则加 -s、-ed、-er 的形式一律不列，只保留真正需要记忆的不规则变化，以及同形异音的读音提示（如 `record` 名动词读音不同）。

**词形与释义分离。** 词形、编号、星级属硬数据，与释义分开放置。修订释义不会误伤结构数据。

**两份排序，各司其职。** 编号序总表便于逐条核对释义与搭配；**字母序总表**便于对照课标原文（A→Z）核验词形与星级。

标「构建产物」的三个目录**不在版本库里**。它们由 `build.py` 从源文件重新生成，内容每次一致，因此不必提交——这样仓库只保留可读可比的文本，改动一目了然。

### 数据模型

三类内容各由一个来源负责，互不重复：

| 来源 | 负责 | 可否手工编辑 |
|---|---|---|
| `defs/*.txt` | 释义、词性、变化、备注 | ✅ |
| `词形表.txt` | 词形 | ✅（改后须 `authority.py sync`） |
| `step4_wordlist.json` | 编号、词形、星级的机器版 | ❌ 由工具维护 |
| `days/DayXX.py` | 骨架，仅声明编号归属 | ❌ 自动生成 |

**为什么这样拆。** 词形和星级来自原始资料与课标的核对结果，一旦改动会牵动排序与检索；释义则需要长期打磨。两者分离后，修订释义不必也无从碰触结构数据。

## 三、凡例

### 词性

| 写法 | 含义 |
|---|---|
| `n. [C]` | 可数名词 |
| `n. [U]` | 不可数名词 |
| `n. [C]&[U]` | 可数兼不可数 |
| `vt.` | 及物动词 |
| `vi.` | 不及物动词 |
| `vt.&vi.` | 及物兼不及物 |
| `linking v.` | 连系动词 |
| `modal v.` | 情态动词 |
| `adj.` `adv.` `conj.` `prep.` `pron.` `det.` `num.` `int.` | 形容词、副词、连词、介词、代词、限定词、数词、感叹词 |

### 标记

| 标记 | 含义 |
|---|---|
| `**` / `*` | 星级：两星＝选择性必修，一星＝必修，无星号＝义务教育阶段 |
| `！` | **无法联想**的熟词生义 |
| **加粗** | **可以联想**的引申义 |

### 「变化」一栏

只列**背规则也推不出来**的形式：不规则复数、不规则过去式与过去分词、不规则比较级与最高级，以及同形异音的读音提示。规则变化一律不列。

本栏末尾也可能出现搭配、易混词、读音等提示（如「搭配 to some extent 在某种程度上」「易混 physicist」），与变化内容以分号相连。两者共处一栏，都是"光看释义看不出来"的提示。

### 编号

编号 1–3185 来自原始资料，**在全表中唯一且连续**，可用作检索与引用的稳定标识。修订时请引用编号，不要只引单词（同形词与变体会混淆）。

## 四、构建

### 你需要装什么

| 你是 | 需要装 |
|---|---|
| 只想用成品 PDF 的读者 | **什么都不用装**，到 Releases 页面下载 |
| 只修订释义、词形的贡献者 | Python + `python-docx` |
| 需要自己出 PDF 的维护者 | 再加 TeX Live（有免安装的办法，见下） |

也就是说，**TeX Live 不是使用本项目的必需品**。这是个词表，不是 LaTeX 项目；LaTeX 只是我们自己出 PDF 用的工具。

### 命令

```powershell
python build.py                # 全部重建（有 TeX Live 时连 PDF 一起出）
python build.py --no-pdf       # 只出 tex/ 与 docx/，不碰 PDF
python build.py D04            # 只重建某一天（不会动总表）
python build.py --alpha-only   # 只出字母序总表
```

只差一个 `python-docx` 的话：

```powershell
python -m pip install python-docx
```

若命令行里没有 `python`，改用完整路径（把路径换成你自己的解释器）：

```powershell
& 'D:\MinerU_Project\.venv\Scripts\python.exe' build.py
```

### 输出

| 文件 | 排序 | 用途 |
|---|---|---|
| `docx/总表.docx`、`build/总表.pdf` | 按天分组，组内按编号升序 | 核对释义、搭配 |
| `docx/总表_字母序.docx`、`build/总表_字母序.pdf` | 全局 A→Z | 对照课标原文核对词形与星级 |
| `docx/DayXX_词汇表.docx`、`tex/DayXX.tex` | 单天 | 分天使用 |

### 没有装 TeX Live 会怎样

**不会报错，也不会中断。** `build.py` 会自动寻找 `xelatex`：先看环境变量 `XELATEX`，再看系统 `PATH`，最后扫常见安装位置（`D:\texlive\…`、`/usr/local/texlive/…`、`/Library/TeX/texbin` 等）。

找不到时，脚本会打印一段提示，把 `tex/` 和 `docx/` 正常生成完毕，然后**跳过 PDF**。你得到的 Word 文件是完整的、可以直接用的。

想自己编 PDF 又不想装几个 GB 的完整 TeX Live，有三种省事的做法：

| 办法 | 说明 |
|---|---|
| **下载成品 PDF** | 最省事。仓库 Releases 页面提供，不必自己编 |
| **装 TinyTeX** | 约几百 MB，`xelatex` 命令同样可用。注意需另装 `ctex`、`fontspec`、`xeCJK`、`longtable`、`booktabs`、`xcolor`、`fancyhdr`、`geometry` 等宏包 |
| **在 GitHub Actions 里编** | 若日后配置了自动构建，CI 会代劳，本机仍无需 TeX |

### 字体：换系统时会遇到的事

PDF 由 xelatex 排版，它**直接调用系统已安装的字体**。项目原先写死 Windows 上才有的字体，换到别的系统就会失败，因此现已改为配置驱动：

- 字体候选写在 **`fonts.json`**（中文一组、拉丁一组，各按优先顺序排列）
- `build.py` 会读取本机字体列表，**自动挑第一个装得上的**
- 一个候选都挑不到时，脚本把本机字体名打印出来，供你填进 `fonts.json`

因此通常情况下**不需要改任何代码**。Linux 上装 `fonts-noto-cjk`（对应 `Noto Sans CJK SC`）、macOS 上用系统自带的 `SimSun` 或思源的静态版本，都能自动命中。

临时应急还可以用环境变量，不必动配置文件：

```powershell
$env:FONT_CJK='SimSun'; $env:FONT_LAT='DejaVu Serif'
$env:XELATEX='D:\texlive\2025\bin\windows\xelatex.exe'
python build.py
```

**关于 Word 文件。** `docx/` 不经过 xelatex，与字体是否安装无关。文件里写的字体名只是「建议」，最终由打开它的电脑决定用哪套字体显示——所以别人收到你的 `.docx` 不会因为缺字体而变成乱码或方框。

### 构建流水线

```
days/DayXX.py（骨架）──取编号──┐
                              ↓
step4_wordlist.json ──词形、星级──┤
                              ↓
defs/*.txt ──释义、变化、备注──→ 合并
                              ↓
              irregular.py 自动补不规则变化
                              ↓
        编号升序总表 ─┬─→ tex/DayXX.tex → tex/总表.tex ──→ xelatex → build/总表.pdf
                      │                              └─→ python-docx → docx/总表.docx
                      │
        字母序总表 ───┴─→ tex/A_DayXX.tex → tex/总表_字母序.tex ──→ xelatex → build/总表_字母序.pdf
                                                              └─→ python-docx → docx/总表_字母序.docx
```

**为什么用 `\input` 而非文本拼接。** 总表只引用各天的片段，改完某一天的 `.tex` 重编译即自动生效，不必在两处维护同一份内容。

## 五、校验工具

```powershell
python check_defs.py       # 释义文件格式校验：编号归属、词性符号、覆盖进度
python audit.py            # 全量校对：覆盖、格式、标记、可疑错位
python align_check.py      # 词义对应抽查
python recompute_tier.py   # 星级判定重算（默认只报告）
python authority.py check  # 词形表是否被改动过
```

`build.py` 在构建前会自动调用 `tier_check.py`。若发现星级判定待重算或粗体标记未闭合，会在输出开头提示，但不中断构建。

## 六、技术约束

以下取值来自实际调试结果，更换环境时需留意。

| 项目 | 取值 | 原因 |
|---|---|---|
| 中文正文字体 | 见 `fonts.json`（Windows 上默认 **Microsoft YaHei**） | 必须有粗体字重。思源系列的可变字体（VF）无法被 xelatex 加载；Noto Sans SC 的某些版本缺少粗体字重，会触发 `xdvipdfmx: Invalid font` 导致编译失败 |
| 拉丁与音标字体 | 见 `fonts.json`（Windows 上默认 **Times New Roman**） | 必须含 IPA 字形（ə ʊ ɪ ɔː），否则音标渲染为空白 |
| 生义标记 | **全角 ！**（U+FF01） | ❗（U+2757）与 ⚠（U+26A0）在常用字体中无字形，会导致编译失败 |
| 行分隔 | `\hline`，0.3pt | PDF 版不能用隔行灰底：LaTeX 的 `\rowcolor` 会覆盖 `\hline`，使横线消失 |

这几条是实测结论，换环境时值得留意。字体由 **`fonts.json`** 控制，脚本会自动挑选本机可用的候选，正常无需改代码；实在挑不到时，按第四节「字体」一节的提示把本机字体名填进去即可。

## 七、贡献方式

**完整格式规范、提交流程与数据出处，见 [修订与贡献指南.md](修订与贡献指南.md)。** 简版：

1. 读 [修订与贡献指南.md](修订与贡献指南.md) 了解释义格式（不需要编程基础）
2. 改 `defs/` 下的释义文件；**若改的是词形，必须走该指南第四节的专门流程**（三个文件要同步）
3. `python check_defs.py` 校验 → `python build.py` 确认无误（**没装 LaTeX 也没关系**，脚本会跳过 PDF，Word 照常生成）
4. 提交改动，并说明依据（词典页码、课标页码、课本页码、课堂讲解等）

**只提交源文件的改动。** `build/`、`docx/`、`tex/` 均为构建产物，他人重新构建即可得到——提交它们只会让仓库迅速变大，而且二进制文件无法逐行比对。

**改了词形的人请特别注意：** 只提 `词形表.txt` 会让别人的构建结果和你不一样。`step4_wordlist.json` 才是构建真正读取的权威数据，`days/DayXX.py` 也需一并更新——`python authority.py sync` 会同时处理好这三个文件。

**没有仓库写权限的**，走 Fork → 分支 → Pull Request；只想改一条又不想碰 git 的，直接开 Issue 写清"文件、编号、原文、改为、依据"五项即可。
